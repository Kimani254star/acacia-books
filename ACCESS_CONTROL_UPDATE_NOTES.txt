Acacia Books Access Control Update (frontend/client-side)

Implemented:
- Non-admin permission checks now fail closed when a module/action permission is absent; explicit true permissions are required.
- Permission matrix includes Lock Period, Unlock Period, and Lock Settings actions.
- Non-admin module/tab navigation requires explicit View permission and role/plan tab inclusion.
- Transaction Lock and Unlock actions require their respective transactionLockingTab permissions.
- Successful lock/unlock actions are written to audit log when logAudit is available.
- Sidebar visibility uses module View permission.

Important limitation:
- This application package is a browser/localStorage-based frontend. These checks are client-side and can be bypassed by a technically skilled user who manipulates browser storage or scripts. Full security enforcement requires server-side authorization checks in the API/database for every read/write and database policy/RLS. The ZIP does not include backend/API source or database policy migrations, so server-side enforcement cannot be implemented or verified here.
- Transaction locks in the current UI are module cutoff locks (up to a date), not a newly built start/end-date period-lock workflow. Existing save wrappers and lock checks should still be tested against every transaction path before production use.
